## 一、JWT 鉴权与权限控制

**JWT（JSON Web Token）鉴权**：用户登录成功后，服务端签发一个带签名的 Token，之后每次请求都在 Header 中携带 Token，服务端验证**签名**和**有效期**，通过解密验证来确认用户身份，无需在服务端保存会话状态。

**权限控制**分两层，通常一起做：

- **前端控制**：不显示无权限的路由（菜单）、不显示无权限的按钮、直接访问不被允许的页面时跳转到 404
- **后端控制**：请求到达对应的端点时，先检查该用户是否有这个权限（如校验 JWT 中携带的权限数组），没有则返回 403

> 注意：前端控制只是体验层面的"隐藏"，真正安全的是后端控制，前端控制可以被绕过

## 三、双 API 负载均衡

- 方案：配置冗余接口 + 故障自动切换机制
- 后台任务定时健康检查：每隔 10s 请求 API 的检查端点，如果主节点出现了问题，立即切换到备用节点，然后流量都请求到备用节点
- 故障自动切换（多层机制）：转发请求到当前活跃节点，若失败（异常 / 非 2xx / 返回 HTML / 非 JSON），立即切换到另一个节点重试

## 四、EF 模型配置

- 数据注解 + 链式配置（Fluent API），主要是配置主键、索引

EF（Entity Framework）模型配置有两种方式，可以混用：

- **数据注解**：直接在实体类属性上加 `[Key]`、`[Required]` 等特性，简单直观
- **链式配置（Fluent API）**：在 `OnModelCreating` 中用链式方法配置，功能更全
- 主要用途是配置主键、索引等数据库结构约束

## 五、数据库关键词

- 视图、存储过程、事务的关键词：`VIEW`、`PROCEDURE`、`TRANSACTION`
  - 视图（VIEW）：封装常用查询，当作虚拟表使用
  - 存储过程（PROCEDURE）：把一段 SQL 逻辑存在数据库端，供重复调用
  - 事务（TRANSACTION）：保证多个操作要么全部成功、要么全部回滚

## 六、依赖注入

- ASP.NET 自带了依赖注入（DI）容器，不需要额外引第三方框架
- 常用三种生命周期注册方式：
  - `AddSingleton`：整个应用共用一个实例
  - `AddScoped`：每次请求共用一个实例
  - `AddTransient`：每次获取都创建新实例
