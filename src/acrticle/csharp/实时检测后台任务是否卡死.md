## 原理

每次后台任务的循环开始就写入一个时间戳到共享的单例服务里面，约定好超过多少分钟算卡死；然后新建一个 API，向外部提供每个后台任务最新写入的时间戳，供外部判断是否卡死；内部再新建一个独立的后台任务，定时扫描共享的单例服务里面所有任务的心跳时间戳，如果发现某个任务超过阈值没有心跳，就认为该任务卡死了，发送信息到钉钉群聊里面。

## 推荐方案：心跳（Heartbeat）+ 健康检查 API + 看门狗（Watchdog）

核心思路分三步：

### 1️⃣ 心跳记录 — 每个任务每轮循环结束时更新时间戳

在每个后台任务的 `while` 循环末尾，记录一个 `DateTime.UtcNow` 到一个共享的单例服务中。如果某个任务的心跳时间戳超过一定阈值（比如 5 分钟）没有更新，就认为该任务卡死了。

### 2️⃣ 健康检查 API — 在 HealthCheckController 中新增接口

外部监控工具（如 Uptime Kuma、定时脚本）可以轮询这个接口，返回类似这样的 JSON：

```json
{
  "BatchWriteNodesValueAsync": {
    "lastHeartbeat": "2026-08-03T08:05:12Z",
    "secondsSinceLastHeartbeat": 3,
    "isAlive": true
  },
  "CheckClearZeroBackgroundTaskAsync": {
    "lastHeartbeat": "2026-08-03T07:58:01Z",
    "secondsSinceLastHeartbeat": 434,
    "isAlive": false
  }
}
```

### 3️⃣ 看门狗任务 — 独立的后台任务自动检测并报警

新增一个轻量级的 `WatchdogBackgroundService`，每隔 1 分钟检查所有任务的心跳，如果发现某个任务超过阈值没有心跳，就：

- 记录 Error 日志
- 发送钉钉告警
