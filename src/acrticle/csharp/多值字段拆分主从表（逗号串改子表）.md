# 多值字段拆分主从表（逗号串改子表）

## 前言

后台系统里经常出现这种设计：主表用一个字段存多个值，多个值用逗号隔开，比如打印模板表的 `ProductCode = "A001,A002,A003"`（一个模板适配多个产品）、工单表的 `OperatorCode = "张三,李四"`（一张工单多个操作员）。

这种「单列逗号串」在数据量小、只展示不查询时还能凑合，但一旦需要**按单个值精确筛选、反查、去重约束**，就会暴露一堆问题。本文给出一套完整的重构方案：把逗号串拆成**主表 + 子表（一行一个值）**，同时保持前后端接口格式不变（仍传逗号串），改造成本最小。

全文以「打印模板库 `PrintTemplateLibrary` ↔ 子表 `PrintTemplateProducts`（一个模板多个产品编号）」为示例，套用到自己的业务时替换命名即可。

## 1. 什么时候需要拆（反模式识别）

出现以下任一信号，说明单列逗号串已经不够用了：

| 信号 | 说明 |
|---|---|
| 需求变成"一个 XX 对应多个 YY" | 典型多值场景 |
| 想把字段改成 `NVARCHAR(MAX)` 存更多值 | MAX 列**不能建索引**，多值只能 `LIKE '%xx%'` 全表扫描 |
| 精确筛选失效 | `WHERE ProductCode = 'A001'` 匹配不到 `"A001,A002"` |
| 下拉选项出现"组合坨" | `DISTINCT(ProductCode)` 得到 `A001,A002` 而不是单个值 |
| 需要"按其中一个值反查主记录" | 逗号串只能 `LIKE '%值%'`，前置通配符走不了索引 |
| 需要防止同一主记录下重复录同一个值 | 逗号串无法用数据库约束保证 |

> 实践中用户常在"要求把字段改长一点"时暴露真实需求（其实是想存多个值），要追问真实业务场景再定方案。如果只是展示、从不按值查询，逗号串也能活——**是否需要按值反查，是决定拆不拆的核心判据**。

## 2. 方案核心思想：[NotMapped] 枢纽

拆表最大的顾虑是改动面大。本方案用一个技巧把改动压到最小：

```
改造前：  前端(逗号串) ↔ Controller ↔ DatabaseService ↔ 主表.ProductCode列
改造后：  前端(逗号串) ↔ Controller ↔ DatabaseService ↔ 主表[NotMapped].ProductCode
                                                    └→ 子表(一行一个值)
```

把主表的旧字段改成 `[NotMapped]` 属性：

- **对前端**：接口格式完全不变，仍然传/收逗号串，前端、Controller、DTO 全都不用感知子表的存在；
- **对数据库**：存储下沉到子表，一行一个值，单值列可以建索引。

也就是说，`[NotMapped]` 字段只是一个"兼容层"：新增/编辑时接收前端逗号串，查询时由子表聚合回填。

## 3. 动手前先问清楚这几个问题

拆表方案里有几个关键决策点，动手前逐项确认（用户答不上来时采用默认建议并明确告知）：

| # | 问题 | 决定什么 | 默认建议 |
|---|---|---|---|
| 1 | 哪个表、哪个字段要拆？分隔符是什么？给一行样例数据 | 主表与拆分目标 | — |
| 2 | 子表除"关联键+值"外还要存什么（数量、状态、时间）？ | 子表列设计 | 只要关联键+值+时间 |
| 3 | 值需要反查吗？（输入一个值找出所有主记录） | 是否建索引、反查接口 | 要反查（这是拆表的核心动机） |
| 4 | 同一主记录下值允许重复吗？ | 复合唯一约束 | 不允许 |
| 5 | 单个值的最大长度？ | 能否建索引（见 4.1） | ≤200 字符 |
| 6 | 旧数据怎么迁？旧列删除还是保留观察期？ | 迁移 SQL 与回滚方案 | 保留观察期 |
| 7 | 有 Excel 批量导入/导出吗？ | 导入解析格式 | 单元格内逗号串 |
| 8 | 要审计日志吗？粒度？ | 变更日志设计 | 整串记一条 |
| 9 | 编辑时子表同步策略？ | 先删后插 vs 差量更新 | 整体先删后插 |
| 10 | 前端怎么录入？ | 控件与数据源 | 手输可多选（allow-create） |

## 4. 数据库设计

> 所有 SQL 生成 `.sql` 文件放到 `navicat的表结构/` 目录，**在 SSMS 里手动执行**，不要让工具直连生产库跑脚本。

### 4.1 子表建表

```sql
-- ============================================================================
-- 打印模板适用产品（PrintTemplateProducts）建表脚本
-- 目标数据库：SQL Server (T-SQL)
-- 说明：一个打印模板可适配多个产品编号，一行一个产品编号
-- ============================================================================
CREATE TABLE [PrintTemplateProducts]
(
    [Id]          INT IDENTITY(1,1) PRIMARY KEY,

    -- 关联主表业务编号（PrintTemplateLibrary.TemplateId）
    [TemplateId]  NVARCHAR(60)  NOT NULL,

    -- 单个产品编号（单值定长，可建索引）
    [ProductCode] NVARCHAR(200) NOT NULL,

    [CreatedTime] DATETIME2     DEFAULT GETDATE(),

    -- 复合唯一约束：同一模板下同一个编号只能出现一次
    CONSTRAINT UQ_PrintTemplateProducts_TemplateId_ProductCode
        UNIQUE ([TemplateId], [ProductCode])
);
GO

-- 值列索引：精确筛选/查重走 Index Seek
CREATE INDEX [IX_PrintTemplateProducts_ProductCode]
    ON dbo.PrintTemplateProducts([ProductCode]);
GO
```

三个设计要点：

1. **关联键用主表业务编号（TemplateId），不用主表自增 Id**——审计日志、Excel 导入都以业务编号为锚，可读可追踪。
2. **值列必须单值定长且 ≤ NVARCHAR(450)**——SQL Server 非聚集索引键上限 900 字节（NVARCHAR 每字符 2 字节），超长就建不了索引，反查退化为全表扫描；`NVARCHAR(MAX)` 更是完全不能建索引。
3. **复合唯一约束一举两得**——既防重，又因为首列是 TemplateId，"按模板加载全部值"的查询直接被这个索引覆盖，无需再建。

### 4.2 主表旧列处理（分两步走）

```sql
-- 第 1 步（观察期）：先保留旧列，只停止读写（代码里字段改 [NotMapped]）
-- 第 2 步（确认子表数据完整后）：再删列
ALTER TABLE [PrintTemplateLibrary] DROP COLUMN IF EXISTS [ProductCode];
```

### 4.3 存量数据迁移（旧列还有数据时）

```sql
-- 把主表逗号串按逗号拆行插入子表（先清空再迁，脚本可重复执行）
TRUNCATE TABLE [PrintTemplateProducts];
INSERT INTO [PrintTemplateProducts] ([TemplateId], [ProductCode], [CreatedTime])
SELECT t.[TemplateId],
       LTRIM(RTRIM(value)),
       GETDATE()
FROM [PrintTemplateLibrary] t
CROSS APPLY STRING_SPLIT(t.[ProductCode], ',')
WHERE t.[ProductCode] IS NOT NULL AND LTRIM(RTRIM(t.[ProductCode])) <> '';
```

迁移后**抽查**：对比几个主记录的子表行数与旧串个数是否一致，确认无误后再执行删列。

### 5.2 主表实体：旧字段加 [NotMapped]

```csharp
/// <summary>
/// 产品编号（多个用逗号隔开）
/// 非数据库列，由子表聚合而来；新增/编辑时用于接收前端传入的逗号串
/// </summary>
[NotMapped]
public string ProductCode { get; set; } = string.Empty;
```

> **注意**：`[NotMapped]` 字段不会被 EF 写入/查询，**禁止**在 `Where(e => e.ProductCode == x)` 里使用它——查出来的记录该字段永远是空的。拆表后要全项目搜索旧字段的引用，所有"直接从主表读该字段"的代码都改为经聚合回填。

### 5.4 两个辅助方法：解析 + 回填

```csharp
/// <summary>
/// 解析多值字符串（多个用逗号/分号隔开，支持中英文符号）为列表
/// 去空、去重、保持原有顺序
/// </summary>
private static List<string> ParseProductCodes(string? productCode)
{
    if (string.IsNullOrWhiteSpace(productCode)) return new List<string>();
    return productCode
        .Split(new[] { ',', '，', ';', '；' },
            StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)
        .Where(c => c.Length > 0)
        .Distinct()          // 去重：与子表唯一约束对齐，避免插入即冲突
        .ToList();
}

/// <summary>
/// 批量加载子表值并回填到实体的 ProductCode 字段（NotMapped，逗号串）
/// 一次 IN 查询完成，避免逐行查库（N+1）
/// </summary>
private static async Task FillProductCodesAsync(QrScanDbContext dbContext,
    IReadOnlyCollection<PrintTemplateLibrary> records)
{
    if (records.Count == 0) return;

    var templateIds = records.Select(r => r.TemplateId).Distinct().ToList();
    var products = await dbContext.PrintTemplateProducts
        .Where(p => templateIds.Contains(p.TemplateId))
        .OrderBy(p => p.Id)
        .ToListAsync();

    var codesByTemplate = products
        .GroupBy(p => p.TemplateId)
        .ToDictionary(g => g.Key, g => string.Join(",", g.Select(p => p.ProductCode)));

    foreach (var r in records)
        r.ProductCode = codesByTemplate.TryGetValue(r.TemplateId, out var codes)
            ? codes
            : string.Empty;
}
```

两个细节：

- **分隔符兼容中英文**（`,，;；`）：用户在 Excel 和手输场景里必然混用中文标点；
- **去重在入库前做**：与子表唯一约束对齐，否则插入时直接撞唯一约束抛异常。

### 5.5 六个 CRUD 的固定套路

主从表的增删改查和普通的增删改查一样，只是需要借助两个辅助方法：**解析**——把前端传来的逗号串解析为列表（写入子表），即 `ParseProductCodes`；**合并**——把查询到的子表列表合并成逗号串（回填展示），即 `FillProductCodesAsync`。

理解了这一点，拆表后所有增删改查都遵循同一套模式：

| 操作 | 套路 | 关键点 |
|---|---|---|
| **分页查询** | 主表分页 → `FillProductCodesAsync` 一次 IN 回填 | 搜索/筛选含值时：先查子表命中 TemplateId 集合，再主表 `Contains`（IN）走索引 |
| **筛选下拉** | 值的选项从**子表** `Distinct` 取 | 主表 NotMapped 字段查库时永远是空的 |
| **新增** | 解析逗号串 → 主表 1 条 + 子表 N 条 → 同一事务 | SqlException 2627/2601 兜底提示并发重复 |
| **更新** | 先加载旧值回填 → 对比生成审计日志 → 有变化才**先删后插** → 同一事务 | 旧值必须在赋新值**之前**取出 |
| **删除** | 同一事务内先删子表再删主表 | 防止"主表删失败但子表已清空"的脏数据 |
| **反查** | 子表精确匹配值 → 取 TemplateId 集合 → 关联主表 | 如"按产品编号查模板列表"接口 |

### 5.8 更新骨架（旧值回填 → 日志 → 先删后插）

```csharp
var record = await dbContext.PrintTemplateLibraries.FirstOrDefaultAsync(e => e.Id == id);
if (record == null) throw new InvalidOperationException($"Id 为 {id} 的记录不存在");

// ① 必须先在生成变更日志之前回填旧值，否则旧值恒为空 → 日志全是"空→新"
var oldProductCodes = await dbContext.PrintTemplateProducts
    .Where(p => p.TemplateId == record.TemplateId)
    .OrderBy(p => p.Id)
    .Select(p => p.ProductCode)
    .ToListAsync();
record.ProductCode = string.Join(",", oldProductCodes);

// ② 规范化新值（去空去重），回写 dto 使日志比对一致
var newProductCodes = ParseProductCodes(dto.ProductCode);
dto.ProductCode = string.Join(",", newProductCodes);

// ③ 再生成字段级变更日志（此时 record 仍是旧值）
//    ProductCode 整串记一条：OldValue="A001,A002" → NewValue="A001,A003"
var changeLogs = BuildUpdateLogsFromDto(record, dto, /* …… */);

// ④ 赋值主表字段……
record.TemplateName = dto.TemplateName;
record.ProductCode = dto.ProductCode;
record.UpdatedTime = DateTime.Now;

using var transaction = await dbContext.Database.BeginTransactionAsync();
try
{
    if (changeLogs.Count > 0)
        await dbContext.PrintTemplateModificationLogs.AddRangeAsync(changeLogs);

    // ⑤ 值串变化才先删后插（无变化不触碰子表，也不产生无意义日志）
    if (string.Join(",", oldProductCodes) != string.Join(",", newProductCodes))
    {
        await dbContext.PrintTemplateProducts
            .Where(p => p.TemplateId == record.TemplateId).ExecuteDeleteAsync();
        if (newProductCodes.Count > 0)
            await dbContext.PrintTemplateProducts.AddRangeAsync(

    }
    await dbContext.SaveChangesAsync();
    await transaction.CommitAsync();
}
catch (SqlException ex) when (ex.Number == 2627 || ex.Number == 2601)
{
    await transaction.RollbackAsync();
```

### 5.9 删除骨架（同一事务，先删子表再删主表）

```csharp
var record = await dbContext.PrintTemplateLibraries.FirstOrDefaultAsync(e => e.Id == id);
if (record == null) return false;

// 子表删除 + 主表删除必须同一事务：
// ExecuteDeleteAsync 是立即执行 SQL，如果不在事务里，
// 子表先落库、主表删除失败时会残留"主记录还在但值被清空"的脏数据
using var transaction = await dbContext.Database.BeginTransactionAsync();
try
{
    await dbContext.PrintTemplateProducts
        .Where(p => p.TemplateId == record.TemplateId)
        .ExecuteDeleteAsync();
    dbContext.PrintTemplateLibraries.Remove(record);
    await dbContext.SaveChangesAsync();
    await transaction.CommitAsync();
}
catch { await transaction.RollbackAsync(); throw; }
return true;
```

### 5.10 按值反查骨架

```csharp
/// <summary>
/// 根据产品编号查询匹配的打印模板列表
/// 子表精确匹配 → 关联主表返回
/// </summary>
public async Task<List<object>> GetTemplatesByProductCodeAsync(string productCode)
{
    using var scope = _scopeFactory.CreateScope();
    var dbContext = scope.ServiceProvider.GetRequiredService<QrScanDbContext>();

    if (string.IsNullOrWhiteSpace(productCode)) return new List<object>();
    var code = productCode.Trim();

    // 子表精确匹配 → 业务编号集合
    var templateIds = await dbContext.PrintTemplateProducts
        .Where(p => p.ProductCode == code)
        .Select(p => p.TemplateId)
        .Distinct()
        .ToListAsync();
    if (templateIds.Count == 0) return new List<object>();

    // 关联主表
    var templates = await dbContext.PrintTemplateLibraries
        .Where(t => templateIds.Contains(t.TemplateId))
        .Select(t => new { t.TemplateId, t.TemplateName, t.Version })
        .ToListAsync();
    return templates.Cast<object>().ToList();
}
```

### 5.11 批量导入（Excel）

Excel 单元格仍填逗号串（用户习惯不变），导入时后端解析拆行。要点：

```csharp
{
    item.TemplateName = item.TemplateName.Trim();
    item.ProductCode = string.Join(",", ParseProductCodes(item.ProductCode));
}

// ② 已存在记录先回填旧值，供变更对比（否则旧值恒为空 → 垃圾日志）
await FillProductCodesAsync(dbContext, existingRecords);

// ③ 循环中只收集，不逐条删插
var productsToInsert = new List<PrintTemplateProduct>();
var templateIdsToReset = new List<string>();
// 更新行：templateIdsToReset.Add(...); productsToInsert.AddRange(...);
// 新增行：productsToInsert.AddRange(...);

// ④ 事务内：先删（仅被更新的主表编号）后插，一次批量完成
if (templateIdsToReset.Count > 0)
    await dbContext.PrintTemplateProducts
        .Where(p => templateIdsToReset.Contains(p.TemplateId))
        .ExecuteDeleteAsync();
if (productsToInsert.Count > 0)
    await dbContext.PrintTemplateProducts.AddRangeAsync(productsToInsert);
```

**不要在循环里逐条删插子表**——收集后一次批量操作，符合"能批量不用循环"的原则。

### 5.12 审计日志粒度

- `ProductCode` **整串记一条**（Old→New），不要逐值记录；
- 标识字段（TemplateId）不作为变更字段；
- 空值陷阱：前端空值传 `""`、数据库旧值是 `null`，对比前先归一化：`(oldVal ?? "") != (newVal ?? "")`。

变更对比函数示例：

```csharp
private static List<PrintTemplateModificationLog> BuildUpdateLogsFromDto(
    PrintTemplateLibrary rec, PrintTemplateLibraryUpdateDto dto,
    string modifiedBy, string modifiedByRealName, DateTime time)
{
    var logs = new List<PrintTemplateModificationLog>();
    void AddStr(string field, string? oldV, string? newV)
    {
        if ((oldV ?? string.Empty) != (newV ?? string.Empty))
            logs.Add(new PrintTemplateModificationLog
            {
                TemplateId = rec.TemplateId, OperationType = "UPDATE", FieldName = field,
                OldValue = oldV, NewValue = newV,
                ModifiedBy = modifiedBy, ModifiedByRealName = modifiedByRealName,
                ModifiedTime = time
            });
    }
    AddStr("TemplateName", rec.TemplateName, dto.TemplateName);
    AddStr("ProductCode",  rec.ProductCode,  dto.ProductCode);   // 逗号串变化也进日志
    AddStr("Version",      rec.Version,      dto.Version);
    return logs;
}
```

Controller 只负责参数校验和调用 DatabaseService；方法用 `#region` 按模块划分，加 `/// <summary>` XML 注释（保证 swagger 有中文说明）。

### 7.2 逗号串 ↔ 数组互转

```js
// 提交：数组 → 逗号串（trim + 过滤空值）
productCode: createForm.productCodes.map(v => String(v).trim()).filter(Boolean).join(',')

// 回显：逗号串 → 数组（支持中英文逗号/分号，去空）
function splitPtProductCodes(value) {
  if (!value) return []
  return String(value).split(/[,，;；]/).map(v => String(v).trim()).filter(v => v.length > 0)
}

// 编辑抽屉打开时（详情接口返回聚合后的逗号串）：
productCodes: splitPtProductCodes(detail.productCode)

// 打开新增时：
productCodes: []
```

## 8. 上线顺序（观察期策略）

对已有数据的表，稳妥的上线顺序是：

```
建子表 → 迁移数据 → 上新代码（停用旧列读写）→ 观察 → 删旧列
```

- 旧列先保留（只停止读写），观察一段时间确认子表数据完整后再删列；
- 删列前先抽查：对比几个主记录的子表行数与旧串个数是否一致；
- 迁移脚本写成可重复执行（先 TRUNCATE 再 INSERT），出错可随时重来。

## 10. 易踩坑清单

1. **旧值回填必须在赋新值之前**——更新时先查子表旧值、生成日志，再赋新值；顺序错了审计日志全是"空→新"。
2. **主表 NotMapped 字段查库恒为空**——全项目搜索旧字段引用，任何"从主表读该字段"的旧代码/旧 SQL 都要改为经聚合回填。
3. **列表回填用一次 IN 查询，禁止循环查库**——用 `templateIds.Contains` 单次查询，避免 N+1。
4. **先删后插与主表操作放同一事务**——`ExecuteDeleteAsync` 是立即执行 SQL，必须入事务，否则产生脏数据。
5. **分隔符兼容中英文**（`,，;；`）——前后端解析都要兼容。
6. **去重在入库前做**——否则复合唯一约束直接抛异常。
7. **值列长度 ≤450 字符才能建索引**——业务上单值超长时应考虑改成关联字典表，而不是加大长度。
8. **筛选下拉从子表取**——从主表 NotMapped 字段取永远是空的。
9. **先删后插 vs 差量更新**——先删后插简单可靠（推荐起步）；子表行数大或需要保留子行 CreatedTime 时才改差量（diff 出要删/要插的集合）。
10. **SQL 文件让用户手动执行**——删旧列前先迁移 + 抽查子表数据完整性。
11. **新增侧边栏页面记得加权限**——默认仅管理员可见，需要在 `RolePermissions` 表加一行数据：

```sql
-- 给 admin 角色添加权限
INSERT INTO [RolePermissions] ([RoleCode], [PermissionCode], [RoleName])
VALUES ('admin', 'telemetry:list', '超级管理员');
```
