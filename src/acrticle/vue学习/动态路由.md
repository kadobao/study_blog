动态路由有两种实现方案：**方案一**是前端根据权限码过滤本地静态路由；**方案二**是后端下发菜单表，前端动态注册路由（本文重点）。

## 方案一：前端权限码过滤静态路由

路由表全部写死在前端，登录时后端只下发该用户的**权限码数组**，前端根据权限码过滤本地路由表，再动态注册。

## 方案二：后端下发动态路由（本文重点）

### 概述

动态路由基本这四个表就行：**菜单表**、**用户表**、**角色表**、**用户额外的权限表**。

先定义角色有哪些权限，然后用户表的字段有角色字段，然后用户额外的权限表，是用户和权限字段，最后使用视图变成一个表（虚拟表），结构就是用户表的其他字段，加上用户具有的全部权限。


### 数据库表设计

#### 菜单表 Menu

```sql
CREATE TABLE [dbo].[Menu] (
    [Id]             INT IDENTITY(1,1) PRIMARY KEY,
    [ParentPath]     NVARCHAR(100)    NULL,                   -- 所属分组路径（父节点）（如 /dashboard-group），NULL=一级菜单
    [Name]           NVARCHAR(64)     NOT NULL DEFAULT N'',   -- 路由name，唯一
    [Path]           NVARCHAR(255)    NOT NULL DEFAULT N'',   -- 路由path
    [Component]      NVARCHAR(255)    NOT NULL DEFAULT N'',   -- 组件路径，目录可填Layout
    [Redirect]       NVARCHAR(255)    NOT NULL DEFAULT N'',   -- 重定向，目录常用
    [Title]          NVARCHAR(64)     NOT NULL DEFAULT N'',   -- 菜单标题
    [Icon]           NVARCHAR(64)     NOT NULL DEFAULT N'',   -- 图标
    [Visible]        INT              DEFAULT 1,              -- 1显示 0隐藏（下线功能不用删数据）
    [Sort]           INT              NOT NULL DEFAULT 0,     -- 排序，越小越前
    [Status]         INT              NOT NULL DEFAULT 1,     -- 状态：0禁用 1启用
    [PermissionCode] NVARCHAR(50)     NULL                    -- 所需权限码（NULL=所有人可见）
);
GO
```

### 菜单层级示例

| Id | 名称     | Path              | PermissionCode | ParentPath        | 说明                     |
|----|----------|-------------------|----------------|-------------------|--------------------------|
| 1  | 数据看板 | /dashboard-group  | NULL           | NULL              | 一级：分组               |
| 2  | 看板中心 | /dashboard-center | dashboard:view | /dashboard-group  | 二级：看板中心（现在是"父节点"，它也有自己的 Path） |
| 3  | 生产看板 | /prod-dashboard   | dashboard:view | /dashboard-center | 三级：挂在二级的 Path 下（指向二级） |
| 4  | 设备看板 | /equip-dashboard  | dashboard:view | /dashboard-center | 三级：挂在二级的 Path 下（指向二级） |
