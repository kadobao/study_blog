1.1 角色权限表 RolePermissions

CREATE TABLE [RolePermissions] (
    [RoleCode] NVARCHAR(20) NOT NULL,                -- 角色代码（对应 Users.Role）
    [PermissionCode] NVARCHAR(50) NOT NULL,          -- 权限代码，如 clock:delete

多值字段拆分主从表（逗号串改子表）

前言

后台系统里经常出现这种设计：主表用一个字段存多个值，多个值用逗号隔开，比如打印模板表的 ProductCode = "A001,A002,A003"（一个模板适配多个产品）、工单表的 OperatorCode = "张三,李四"（一张工单多个操作员）。

这种「单列逗号串」在数据量小、只展示不查询时还能凑合，但一旦需要按单个值精确筛选、反查、去重约束，就会暴露一堆问题。本文给出一套完整的重构方案：把逗号串拆成主表 + 子表（一行一个值），同时保持前后端接口格式不变（仍传逗号串），改造成本最小。

实时检测后台任务是否卡死

原理

每次后台任务的循环开始就写入一个时间戳到共享的单例服务里面，约定好超过多少分钟算卡死；然后新建一个 API，向外部提供每个后台任务最新写入的时间戳，供外部判断是否卡死；内部再新建一个独立的后台任务，定时扫描共享的单例服务里面所有任务的心跳时间戳，如果发现某个任务超过阈值没有心跳，就认为该任务卡死了，发送信息到钉钉群聊里面。

推荐方案：心跳（Heartbeat）+ 健康检查 API + 看门狗（Watchdog）

核心思路分三步：

1️⃣ 心跳记录 — 每个任务每轮循环结束时更新时间戳

在每个后台任务的 while 循环末尾，记录一个 DateTime.UtcNow 到一个共享的单例服务中。如果某个任务的心跳时间戳超过一定阈值（比如 5 分钟）没有更新，就认为该任务卡死了。
