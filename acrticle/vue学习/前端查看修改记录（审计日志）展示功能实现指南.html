前端查看修改记录（审计日志）展示功能实现指南

描述

本指南 提供了在 Vue 3 + Element Plus + ASP.NET Core 项目中实现修改记录（审计日志）展示功能的完整指南。适用于需要在管理界面中展示实体数据变更历史的场景，如用户管理、设备管理、订单管理等。

实现思路（核心架构）

后端审计日志记录

当实体发生变更时（新增/修改/删除操作），采用字段级变更追踪机制记录审计日志：

  1. 变更检测：只记录实际发生变化的字段，避免记录无意义的日志
  2. 日志内容：每条审计日志包含：
    • 实体信息：实体ID、实体名称（冗余存储便于查询）
    • 变更详情：操作类型（INSERT/UPDATE/DELETE）、字段名（将前端和数据库进行比例，然后记录变化字段）、
      旧值（从数据库查询）、新值（前端提供新值）
    • 操作者信息：修改人用户名、修改人中文名（从 JWT Token 获取）
    • 时间信息：修改时间（DateTime.Now）
  3. 性能优化：使用批量插入（AddRangeAsync）一次性写入多条字段变更日志
  4. 安全处理：敏感字段（如密码）只记录"已修改"状态，不记录具体值
  5. 权限控制：只有管理员可查看审计日志，确保敏感数据安全

前端展示流程

通过时间轴组件展示审计日志，提供清晰的变更历史可视化：

  1. 数据获取：前端调用 REST API 获取指定实体的审计日志，API返回按修改时间倒序排列的日志列表
  2. 时间轴渲染：使用 Element Plus 的 el-timeline 组件展示审计日志：
    • 时间节点：显示修改时间（精确到秒）
    • 卡片内容：
      • 操作类型标签：INSERT（绿色）、UPDATE（蓝色）、DELETE（红色）
      • 字段名：中文映射显示（如 RealName 显示为"真实姓名"）
      • 变更详情：
        • INSERT：显示"设置为：新值"
        • DELETE：显示"原值为：旧值"
        • UPDATE：显示"旧值 → 新值"（箭头连接）
      • 操作者信息：显示修改人中文名
  3. 值格式化：应用字段值格式化函数，将原始值转为中文显示：
    • IsBanned：显示为"已封禁/正常"
    • Role：显示为"超级管理员/经理/普通用户"
    • 其他枚举值：映射为中文名称
  4. 用户体验：最新变更优先展示，清晰区分不同操作类型

核心特性总结

特性说明

一、ASP.NET Core 核心知识点

在实现修改记录功能前，需要掌握以下三个关键知识点。

1.1 解析 Token 获取用户信息

用途：在记录审计日志时，需要获取当前操作者的用户名和中文名，用于填充 ModifiedBy 和 ModifiedByRealName 字段。

实现方式：

/// <summary>
/// 从 JWT Token 中获取当前用户名
/// </summary>
protected string GetCurrentUserName()
{
    // ClaimTypes.Name: JWT Token 中存储的用户名（在 token 定义时设置）
    return User.FindFirst(ClaimTypes.Name)?.Value ?? "未知用户";
}

/// <summary>
/// 从 JWT Token 或数据库中获取当前用户中文名
/// </summary>
protected async Task<string> GetCurrentUserRealName()
{
    var userName = GetCurrentUserName();
    // 从数据库查询用户信息获取 RealName
    var users = await _databaseService.GetByConditionAsync<User>(u => u.UserName == userName);
    return users.FirstOrDefault()?.RealName ?? userName;
}

/// <summary>
/// 从 JWT Token 中获取当前用户角色
/// </summary>
protected string GetCurrentUserRole()
{
    // ClaimTypes.Role: JWT Token 中存储的角色信息
    return User.FindFirst(ClaimTypes.Role)?.Value ?? "normal";
}

Token 构成说明：

  • JWT Token 在生成时包含：username (ClaimTypes.Name), role (ClaimTypes.Role), realName (自定义 claim)
  • 通过 User.FindFirst(ClaimTypes.XXX) 可从 Token 中提取这些信息
  • 不需要每次查询数据库，性能更优

在审计日志中使用：

// 在更新实体时记录审计日志
var modifiedBy = GetCurrentUserName();        // 操作者用户名
var modifiedByRealName = await GetCurrentUserRealName(); // 操作者中文名

await _databaseService.AddAsync<UserModificationLog>(new UserModificationLog
{
    UserId = userId,
    ModifiedBy = modifiedBy,
    ModifiedByRealName = modifiedByRealName,
    OperationType = "UPDATE",
    FieldName = "Role",
    OldValue = oldRole,
    NewValue = newRole,
    ModifiedTime = DateTime.Now
});

1.2 路由参数占位符

用途：设计 API 接口时，通过 URL 路径传递实体 ID，如获取指定用户的修改记录。

路由模板语法：

// 1. 路由模板中用 {参数名} 做占位符
[HttpGet("modification-logs/{userId}")]
//              ↑↑↑↑↑↑   占位符，名字必须和方法参数一致

// 2. 方法参数名和占位符同名，框架自动从 URL 路径中提取
public async Task<IActionResult> GetModificationLogs(int userId)
//                                              ↑↑↑↑↑
//                                              和 {userId} 同名，自动绑定
{
    // userId 的值来自 URL 路径，如 /api/user/modification-logs/5 → userId = 5
    var logs = await _databaseService.GetByConditionAsync<UserModificationLog>(l => l.UserId == userId);
    return Ok(logs);
}

完整路由示例：

// UserController.cs 中已实现的 API 路由
[HttpGet("modification-logs/{userId}")]           // GET /api/user/modification-logs/5
[HttpPut("ban/{userId}")]                         // PUT /api/user/ban/5
[HttpPut("update/{userId}")]                      // PUT /api/user/update/5
[HttpDelete("delete/{userId}")]                   // DELETE /api/user/delete/5

路由参数 vs 查询字符串：

  • 路径参数 {userId}：必需参数，体现在 URL 路径中，如 /api/user/5
  • 查询字符串 ?page=1：可选参数，体现在 URL 参数中，如 /api/user?page=1&size=10

1.3 从 HTTP 请求体提取 JSON 数据

用途：前端发送更新请求时，将修改数据以 JSON 格式放在请求体中，后端需要提取并解析。

[FromBody] 特性工作流程：

前端发送请求:
PUT /api/user/update/5
Body: { "role": "admin", "realName": "张三", "isBanned": false }
     ↓
框架看到参数上有 [FromBody] 特性
     │
     ▼
框架知道: "这个参数的值要从 HTTP 请求体中读取"
     │
     ▼
不走路由值/查询字符串，直接读取请求体流
     │
     ▼
JSON 反序列化为 C# 对象

实现示例：

// 定义请求体 DTO 类
public class UpdateUserRequest
{
    public string? Role { get; set; }
    public string? RealName { get; set; }
    public bool? IsBanned { get; set; }
    public string? Password { get; set; }
    public bool? IsNewcomer { get; set; }
    public int? SkillLevel { get; set; }
    public decimal? WorkHourConversionRatio { get; set; }
    public int? EntryDays { get; set; }
    public int? FastForwardDays { get; set; }
    public int? EmployeeLevel { get; set; }
}

// Controller 方法接收请求体
[HttpPut("update/{userId}")]
public async Task<IActionResult> UpdateUser(int userId, [FromBody] UpdateUserRequest request)
//                                         ↑↑↑↑↑↑            ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑
//                                         路径参数            请求体参数
{
    // request 对象已自动从 JSON 请求体解析完成
    if (!string.IsNullOrEmpty(request.Role))
    {
        user.Role = request.Role;
    }
    // ...处理其他字段
}

前端调用示例：

// src/api/index.js
async function updateUser(userId, updateData) {
    return request.put(`/user/update/${userId}`, updateData)
    //                         ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑  ↑↑↑↑↑↑↑↑↑↑↑↑
    //                         路径参数 userId      请求体 updateData(JSON)
}

// 调用时
await userApi.update(5, {
    role: 'admin',
    realName: '张三',
    isBanned: false
})
// 实际请求: PUT /api/user/update/5
//          Body: { "role": "admin", "realName": "张三", "isBanned": false }

注意事项：

  • 一个方法只能有一个 [FromBody] 参数（请求体只有一个）
  • 复杂对象必须使用 [FromBody]，简单类型可以使用 [FromQuery] 或 [FromRoute]
  • 前端必须发送正确的 JSON 格式，否则反序列化失败

二、数据库表创建模板

2.1 SQL 建表语句

-- 通用修改记录表模板（根据实体替换 Entity）
CREATE TABLE [EntityModificationLogs] (
    [Id] INT IDENTITY(1,1) PRIMARY KEY,              -- 自增主键
    [EntityId] INT NOT NULL,                         -- 被修改的实体 ID（类型根据实际调整，如 NVARCHAR(50)）
    [EntityName] NVARCHAR(50),                       -- 被修改实体的名称（冗余存储，便于审计展示）
    [OperationType] NVARCHAR(10) NOT NULL,           -- 操作类型 (INSERT/UPDATE/DELETE)
    [FieldName] NVARCHAR(100) NOT NULL,              -- 变更的字段名，如 'RealName'
    [OldValue] NVARCHAR(500),                        -- 变更前的值（INSERT 时为 NULL）
    [NewValue] NVARCHAR(500),                        -- 变更后的值（DELETE 时为 NULL）
    [ModifiedBy] NVARCHAR(50) NOT NULL,              -- 修改人 (操作者用户名)
    [ModifiedByRealName] NVARCHAR(50) NOT NULL,      -- 修改人中文名
    [ModifiedTime] DATETIME2 DEFAULT GETDATE(),      -- 修改时间
    [Remark] NVARCHAR(500)                           -- 备注
);

-- 创建索引（提升查询性能）
CREATE INDEX IX_EntityModificationLogs_EntityId ON [EntityModificationLogs]([EntityId]);
CREATE INDEX IX_EntityModificationLogs_ModifiedTime ON [EntityModificationLogs]([ModifiedTime]);

2.2 字段说明和最佳实践

字段名类型说明最佳实践
IdINT自增主键使用 IDENTITY(1,1) 自动生成
EntityIdINT/NVARCHAR实体 ID根据实际实体类型选择，如设备 ID 可能是字符串
EntityNameNVARCHAR(50)实体名称冗余存储，便于审计展示，避免关联查询
OperationTypeNVARCHAR(10)操作类型固定值：INSERT/UPDATE/DELETE
FieldNameNVARCHAR(100)字段名使用属性名，如 "RealName"、"Role"
OldValueNVARCHAR(500)旧值INSERT 时为 NULL，敏感字段用 "***" 代替
NewValueNVARCHAR(500)新值DELETE 时为 NULL，敏感字段用 "***" 代替
ModifiedByNVARCHAR(50)操作者用户名从 JWT Token 中获取，使用 ClaimTypes.Name
ModifiedByRealNameNVARCHAR(50)操作者中文名从数据库查询或 Token 中获取
ModifiedTimeDATETIME2修改时间使用 DateTime.Now 或 GETDATE()
RemarkNVARCHAR(500)备注可选字段，用于记录特殊说明

索引配置建议：

  • EntityId 索引：按实体查询修改记录时使用（必需）
  • ModifiedTime 索引：按时间排序时使用（必需）
  • 复合索引：[EntityId], [ModifiedTime] DESC（可选，优化常见查询）

五、控制器 API 实现模板

5.1 获取修改记录 API（GET 方法）

/// <summary>
/// 获取指定实体的修改记录（审计日志），按修改时间倒序排列
/// </summary>
/// <param name="entityId">实体 ID</param>
/// <returns>修改记录列表</returns>
[HttpGet("modification-logs/{entityId}")]
public async Task<IActionResult> GetModificationLogs(int entityId)
{
    // 权限检查：只有管理员可以查看修改记录
    var currentUserRole = User.FindFirst(ClaimTypes.Role)?.Value;
    if (currentUserRole != "admin")
    {
        return StatusCode(403, new { message = "只有管理员可以查看修改记录" });
    }

    // 从数据库查询修改记录
    var logs = await _databaseService.GetByConditionAsync<EntityModificationLog>(l => l.EntityId == entityId);

    // 按修改时间倒序排列，并转换为前端友好的格式
    var sortedLogs = logs
        .OrderByDescending(l => l.ModifiedTime)
        .Select(l => new
        {
            id = l.Id,
            entityId = l.EntityId,
            entityName = l.EntityName,
            operationType = l.OperationType,
            fieldName = l.FieldName,
            oldValue = l.OldValue,
            newValue = l.NewValue,
            modifiedBy = l.ModifiedBy,
            modifiedByRealName = l.ModifiedByRealName,
            modifiedTime = l.ModifiedTime,
            remark = l.Remark
        })
        .ToList();

    return Ok(sortedLogs);
}

六、审计日志记录逻辑模板

6.1 新增实体时记录（INSERT）

/// <summary>
/// 新增实体并记录审计日志
/// </summary>
[HttpPost("add")]
public async Task<IActionResult> AddEntity([FromBody] AddEntityRequest request)
{
    // 权限检查

    if (currentUserRole != "admin")
    {
        return StatusCode(403, new { message = "只有管理员可以新增实体" });

    // 创建新实体
    var newEntity = new Entity
    {
        Field1 = request.Field1,
        Field2 = request.Field2,

    await _databaseService.AddAsync(newEntity);

            EntityName = newEntity.Name,
            OperationType = "INSERT",

            NewValue = newEntity.Field1?.ToString(),

            ModifiedByRealName = modifiedByRealName,
            ModifiedTime = insertTime
        },
        new EntityModificationLog
        {
            EntityId = newEntity.Id,
            EntityName = newEntity.Name,
            OperationType = "INSERT",
            FieldName = "Field2",
            OldValue = null,
            NewValue = newEntity.Field2?.ToString(),
            ModifiedBy = modifiedBy,
            ModifiedByRealName = modifiedByRealName,
            ModifiedTime = insertTime
        }
        // ...为其他重要字段记录
    };

    // 批量插入审计日志
    await _databaseService.AddRangeAsync(auditLogs);

    return Ok(new { message = "新增成功", entityId = newEntity.Id });
}

6.2 更新实体时记录（UPDATE，字段级比较）

关键点：只记录实际发生变化的字段，避免记录无意义的日志。

💡 重要提示：前端只需全量提供数据，后端自动比对变化

前端在更新实体时，可以提供完整的实体数据（包含未修改的字段），后端会：

  1. 先从数据库查询实体当前的完整数据（旧值）
  2. 接收前端提供的完整更新数据（新值）
  3. 自动比对新旧数据，识别哪些字段发生了变化
  4. 只为实际变化的字段生成审计日志，未变化的字段不记录

优势：

  • ✅ 前端无需复杂的字段变化检测逻辑
  • ✅ 后端保证审计日志的准确性和完整性
  • ✅ 减少无意义的日志记录，节省存储空间
  • ✅ 防止前端遗漏修改字段的记录
/// <summary>
/// 更新实体并记录字段级审计日志
/// </summary>
[HttpPut("update/{entityId}")]
public async Task<IActionResult> UpdateEntity(int entityId, [FromBody] UpdateEntityRequest request)
{
    // 权限检查
    var currentUserRole = User.FindFirst(ClaimTypes.Role)?.Value;
    if (currentUserRole != "admin")
    {
        return StatusCode(403, new { message = "只有管理员可以修改实体" });
    }

    // 查询现有实体
    var entities = await _databaseService.GetByConditionAsync<Entity>(e => e.Id == entityId);
    var entity = entities.FirstOrDefault();

    if (entity == null)
    {
        return NotFound(new { message = "实体不存在" });
    }

    // 保存修改前的旧值，用于审计日志
    var oldField1 = entity.Field1;
    var oldField2 = entity.Field2;
    var oldField3 = entity.Field3;
    // ...保存其他字段的旧值

    // 更新实体字段
    if (!string.IsNullOrEmpty(request.Field1))
    {
        entity.Field1 = request.Field1;
    }
    if (!string.IsNullOrEmpty(request.Field2))
    {
        entity.Field2 = request.Field2;
    }
    // ...更新其他字段

    // 保存更新到数据库
    await _databaseService.UpdateAsync(entity);

    // 生成字段级变更审计日志（只记录实际发生变化的字段）
    var modifiedBy = GetCurrentUserName();
    var modifiedByRealName = await GetCurrentUserRealName();
    var updateTime = DateTime.Now;
    var changeLogs = new List<EntityModificationLog>();

    // 辅助方法：添加变更日志（只在新旧值不同时记录）
    void AddChangeLog(string fieldName, string? oldVal, string? newVal)
    {
        if (oldVal != newVal)
        {
            changeLogs.Add(new EntityModificationLog
            {
                EntityId = entityId,
                EntityName = entity.Name,
                OperationType = "UPDATE",
                FieldName = fieldName,
                OldValue = oldVal,
                NewValue = newVal,
                ModifiedBy = modifiedBy,
                ModifiedByRealName = modifiedByRealName,
                ModifiedTime = updateTime
            });
        }
    }

    // 记录每个字段的变更（只记录实际变化的字段）
    AddChangeLog("Field1", oldField1?.ToString(), entity.Field1?.ToString());
    AddChangeLog("Field2", oldField2?.ToString(), entity.Field2?.ToString());
    AddChangeLog("Field3", oldField3?.ToString(), entity.Field3?.ToString());
    // ...记录其他字段

    // 批量插入审计日志
    if (changeLogs.Any())
    {
        await _databaseService.AddRangeAsync(changeLogs);
    }

    return Ok(new { message = "更新成功" });
}

十、最佳实践和注意事项

10.1 性能优化

  1. 批量插入日志记录

    • 使用 AddRangeAsync 一次性插入多条日志，避免逐条插入
    • 示例：await _databaseService.AddRangeAsync(changeLogs);

  2. 只记录实际变化的字段

    • 使用字段级比较，只在新旧值不同时记录
    • 避免记录无意义的日志，减少数据库写入压力

  3. 添加索引

    • 为 EntityId 和 ModifiedTime 创建索引
    • 优化查询性能：按实体查询、按时间排序

10.2 安全考虑

  1. 敏感字段处理

    • 密码等敏感字段只记录"已修改"，不记录具体值
    • 示例：
    if (passwordChanged)
{
    changeLogs.Add(new EntityModificationLog
    {
        FieldName = "Password",
        OldValue = "***",
        NewValue = "***",
        Remark = "密码已修改"
    });
}

  2. 权限检查

    • 只有管理员可查看修改记录（currentUserRole != "admin"）
    • 其他用户无权访问敏感审计数据

  3. 冗余存储 EntityName

    • 便于审计展示，避免关联查询
    • 即使实体被删除，审计日志仍可追溯

10.3 用户体验

  1. 时间轴倒序展示

    • 最新变更优先展示，符合用户阅读习惯
    • 使用 .OrderByDescending(l => l.ModifiedTime)

  2. 操作类型颜色区分

    • INSERT（绿色 success）：新增操作
    • UPDATE（蓝色 primary）：修改操作
    • DELETE（红色 danger）：删除操作

  3. 字段值格式化

    • 将原始值转为中文显示，提升可读性
    • 示例：IsBanned 显示为 "已封禁/正常"，Role 显示为 "超级管理员/经理/普通用户"

十一、常见问题解答

Q1: 为什么需要冗余存储 EntityName？

A: 冗余存储 EntityName 便于审计展示，避免关联查询。即使实体被删除，审计日志仍可追溯实体名称。

Q2: 如何处理敏感字段（如密码）的审计日志？

A: 对于敏感字段，只记录"已修改"状态，不记录具体值。使用 OldValue = "***" 和 NewValue = "***" 代替实际值。

Q3: 为什么使用批量插入而不是逐条插入？

A: 批量插入 AddRangeAsync 性能更优，减少数据库往返次数，降低系统负载。

Q4: 如何确保只记录实际变化的字段？

A: 在更新实体时，先保存旧值，然后使用辅助方法 AddChangeLog 比较新旧值，只在新旧值不同时记录。

Q5: 前端如何格式化显示字段值？

A: 使用 formatFieldValue 函数根据字段名进行特殊格式化，如将 'True' 转为 "已封禁"，将角色代码转为中文名称等。
